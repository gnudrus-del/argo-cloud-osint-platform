Domande frequenti

Le cose che chiedete più spesso.

È veramente open source? Anche per uso commerciale?

Sì. Licenza Apache 2.0: puoi self-hostare, modificare, distribuire e usare Argo commercialmente. L'unica cosa che ti chiediamo è di mantenere il copyright notice nei file che redistribuisci. Nessun "modello dual", nessun "core+enterprise": un solo codice, uno solo per tutti.

Come garantite che nessun dato dei miei target finisca da voi?

Non ti chiediamo di installare nulla di nostro come dipendenza runtime. Argo gira interamente sulla tua VM o macchina. Non c'è telemetria, non c'è "ping home". Le API BYOK (Shodan, VirusTotal, HIBP, ecc.) le chiami direttamente tu con la tua chiave — noi non le intermediamo. Puoi verificarlo con strace o dal codice.

Come si self-hosta? Serve un ops team?

Setup: git clone, python -m venv, pip install, systemd unit, Caddy davanti per HTTPS. Il repo include deploy_artifacts/ con installer, Caddyfile pronto, docker-compose opzionale per Neo4j/Postgres/Redis. Misure reali dall'istanza demo (Ubuntu 24.04 su Oracle Cloud, 1 vCPU / 5.9 GB): il processo Argo occupa ~57 MB RSS, il sistema completo ~700 MB, la cartella /opt/argo-osint è 109 MB, load average stabile a 0.00. In teoria basta molto meno di 4 GB, ma non abbiamo ancora misurato l'uso continuativo sotto carico reale. Il nostro primo deploy ha richiesto ~45 minuti includendo debug della security list Oracle; su una Ubuntu pulita senza sorprese di rete dovrebbe essere sensibilmente più rapido.

Cos'è la "catena audit court-ready" in pratica?

Ogni evento (login, ricerca, finding, cancellazione) viene appeso a una lista di record. Ogni record contiene: timestamp, actor, action, details, previous_hash, hash (SHA-256 dell'evento + del precedente). Modificare un evento in mezzo alla catena invalida tutti gli hash successivi — la manomissione è rilevabile con una comando. È il pattern usato da Certificate Transparency e da Git.

Perché "italiano"? Cosa cambia rispetto ad altri tool OSINT?

Argo nasce con l'idea che l'OSINT professionale in Italia (e in UE) ha requisiti specifici: GDPR, base giuridica documentata per ogni caso, Rules of Engagement firmate, DSAR pronti, retention configurabile. Non è un tool americano tradotto: è pensato per la compliance italiana ed europea dal giorno zero. UI, documentazione, warning e report escono in italiano nativo.

Quali connettori posso usare senza pagare nessuno?

Su 63 connettori totali, 46 sono no-key: crt.sh, RDAP, DNS, TLS cert, Wayback, Gravatar, GDELT, Nominatim, PhishTank, OpenPhish, subdomain enumeration, port scan (attivo, gated), holehe, maigret, telegram checker, ecc. I 17 BYOK (Shodan, VirusTotal, HIBP, ContactOut, Lusha, ecc.) diventano disponibili nel momento in cui incolli la tua chiave nel tab "Chiavi API".

Posso contribuire? Come si aggiunge un connettore?

Sì, PR benvenute. Un connettore è una classe che estende BaseConnector, dichiara uno spec tipizzato (input types, rate limit, cache TTL, legal note) e implementa _fetch(). Con un test offline che simula l'output. Il pattern è documentato in CONTRIBUTING.md con un template minimale. Regole d'oro: passivo di default, degradazione graceful se manca la chiave, nessun servizio SaaS obbligatorio.

C'è supporto commerciale? Formazione? Deploy on-premise per aziende?

Il progetto è mantenuto volontariamente e non ha ancora una struttura commerciale. Non c'è un canale di supporto paid, non c'è un team che risponde a ticket, non ci sono contratti SLA. Se hai bisogno di deploy assistito o formazione, per ora la strada realistica è farlo internamente col codice open. Il codice free-and-open resta sempre completamente utilizzabile.

Azioni suggerite

Routing OPSEC

controllato dal piano

L'OPSEC routing e gestito automaticamente dal planner in base al caso, al tipo di target e ai flag di autorizzazione.

  • Standard protetto: default per target autorizzati senza necessità di isolamento.
  • Mozilla/Firefox dedicato: attivato se la sorgente richiede un profilo separato.
  • Tor isolato: obbligatorio per dark/deep web flaggato.
  • Multi-provider: usato quando esistono API configurate per più motori.

Audit e logging

Gratuito
  • Audit log con hash chain SHA-256 — ogni evento e tracciabile.
  • Login con IP loggato per accountability.
  • Email di verifica obbligatoria al primo signup.
  • Sessioni HttpOnly, CSRF, Secure cookie.
  • GDPR by-design: DSAR export/erase, tombstone, RoPA.
